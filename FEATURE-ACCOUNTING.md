# Pixelset Replica: Full Feature Accounting

Summary: This accounting covers 365 features taken from the Pixieset research inventory dated 18 Nov 2026, checked against the replica build spec, the build notes including every Simplifications section, and spot checks of the app code. Of those, 335 are BUILT, 16 are PARTIAL, and 14 are NOT BUILT (recounted row by row in the final pass, 19 Nov 2026, after the night build and a code re-audit that found several features built in earlier phases but never credited). Built means the feature works in the replica as a client or photographer would use it. Partial means a working version exists but is simplified, mocked, logged instead of sent, or missing part of the researched behaviour, and the row says exactly how. Not built means there is no working version in the app. Money movement, real email delivery, lab fulfilment, and subscription billing are mocked or display only throughout, because this is a self hosted replica with no live processor, mail, lab, or billing accounts connected. The photo cloud storage product is not mixed into these counts as a feature gap. It is listed once at the end under Excluded by owner's order.

How to read the notes: for every PARTIAL and NOT BUILT row, the note gives the plain reason in everyday language and then says what it would take to finish it after the words "To finish:".

## The short list of real gaps

These are the not built and partial items a paying photographer would actually notice in daily work, ranked by how much they would feel the absence (rewritten in the final pass to match the rows above).

1. No real money movement anywhere yet. Store checkout, invoice payments, booking retainers, and Tap to Pay run on complete processor code paths (Stripe, Stripe Connect, PayPal) that stay parked by the owner's order until a live processor account is connected. One connection closes this across the app.
2. No real email delivery until the owner's Resend key is added. Invites, confirmations, reminders, automation emails, and download links are recorded or logged instead of sent, because no mail service is connected yet. The mailer is built and env gated; one key closes most of this gap at once.
3. No built in email campaigns. The Campaign models, the opt in audience capture, and per plan send quotas all exist, but there is no campaign builder or sender, so the quota has nothing to meter.
4. No Lightroom Classic plugin. The Tools page holds the API token and authenticated upload endpoint a plugin would use, but the plugin itself is not built.
5. No team member logins. Owner, Assistant, and Second Shooter roles exist with enforced permissions and a role preview switcher, but team members are records, not accounts, so nobody on the team can sign in as themselves.
6. No translated interface text. Gallery and dashboard language fields exist, but every string is still English.
7. Partner labs beyond the Prodigi adapter are not integrated. WHCC, ProDPI, Miller's and Mpix, Fujifilm Canada, Loxley Colour, and Atkins Pro are not selectable as working labs.
8. No support chat and no help centre inside the app.
9. Volume photography has no CSV import, and there is no multi gallery bulk edit or one share link for a whole folder of collections.
10. The Photo Editor add on and live charge refunds stay partial while billing is parked: the add on wall and activation are real but simulated, RAW editing works on the embedded JPEG preview rather than raw sensor data, and refunds of live charges arrive only with a live processor.
